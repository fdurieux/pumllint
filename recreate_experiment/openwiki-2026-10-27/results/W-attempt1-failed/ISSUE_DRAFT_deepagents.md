**Title:** `FilesystemBackend.delete` in virtual mode returns `Error deleting …: ENOENT` instead of "not found" when a parent directory is missing

### Summary

In `virtualMode`, `FilesystemBackend.delete(path)` reports a missing target in two different ways, depending on *which* segment is missing:

| target | parent dir | result |
|---|---|---|
| `/absent.md` | exists | `{ error: "Error: '/absent.md' not found" }` |
| `/a/b/absent.md` | `/a` missing | `{ error: "Error deleting '/a/b/absent.md': ENOENT: no such file or directory, lstat '<root>/a'" }` |

Both describe the same state: there is nothing to delete. Callers that check for "not found" to make delete idempotent therefore treat the second case as a real failure. This breaks OpenWiki (langchain-ai/openwiki): its page-retry path deletes a not-yet-written page under a not-yet-created directory, gets the ENOENT form, and aborts the whole `openwiki --init`.

### Versions

- Present at `main` `bf83c27` (2026-10-26, `libs/deepagents` 1.16.0), read from source.
- Reproduced by running 1.13.2 (the version openwiki 0.7.2 pins), Node 22.22.0, Linux.

### Cause

`libs/deepagents/src/backends/filesystem.ts`:

- `delete()` (~L608) calls `resolveDeletePath()`, i.e. `assertRealPathWithinRoot(…, { includeLeaf: false })`.
- In `assertRealPathWithinRoot` (~L136), the walk over the parent segments `lstat`s each one. With `includeLeaf: false` any error is rethrown (`if (!includeLeaf) { throw e; }`), including a plain `ENOENT` on a missing parent.
- `delete()`'s catch-all then wraps it as `Error deleting '<p>': <message>`. The `if (!stat) return { error: "Error: '<p>' not found" }` branch, which already handles a missing leaf, is never reached.

### Reproduction

```js
// node repro.mjs <empty-dir>
import { FilesystemBackend } from "deepagents";
const b = new FilesystemBackend({ rootDir: process.argv[2], virtualMode: true });
console.log(await b.delete("/absent.md"));
// { error: "Error: '/absent.md' not found" }
console.log(await b.delete("/a/b/absent.md"));
// { error: "Error deleting '/a/b/absent.md': ENOENT: no such file or directory, lstat '<dir>/a'" }
```

### Suggested fix

A missing parent means the target cannot exist, so return the same not-found result as a missing leaf. For example, in `delete()`:

```ts
let deletePath: string;
try {
  deletePath = await this.resolveDeletePath(resolvedPath, filePath);
} catch (e) {
  if ((e as NodeJS.ErrnoException)?.code === "ENOENT") {
    return { error: `Error: '${filePath}' not found` };
  }
  throw e;
}
```

The other option is to stop the parent walk on `ENOENT` when `includeLeaf` is false and let the existing `lstat(deletePath)` miss produce "not found". The containment check still runs on the deepest existing segment, so nothing outside the root becomes deletable. Other errors (`ENOTDIR`, `EACCES`, the outside-root error) keep their current behaviour, so the existing ENOTDIR test is unaffected.

A test beside the existing `"missing.txt"` case:

```ts
it("returns not found when a parent directory is missing (virtual mode)", async () => {
  const backend = new FilesystemBackend({ rootDir: tmpDir, virtualMode: true });
  const result = await backend.delete("/missing-dir/missing.txt");
  expect(result.path).toBeUndefined();
  expect(result.error).toContain("not found");
});
```
