Knowledge lives at every layer, and a gap cascades downstream

Business rules and processes

Eligibility, pricing, exceptions, who may approve.

Lost: the reason for a rule and its exception paths, when the analyst or the product expert leaves.

Requirements

What the system must do, in words.

Lost: the unstated assumptions, when the author leaves. The text drifts from the code.

Architecture

Module layout, interfaces, data contracts, dependencies.

Lost: why a boundary is where it is. A contract that says one thing while the code does another.

Code

What the system actually does, defects included.

Lost: the reason behind every rule it applies. Orphaned code goes unread.

Operations

Runbooks, incident handling, deployment rituals, who to call.

Lost: with the operator. The ritual nobody wrote down.

Each layer is written down in its specifications: process models, requirements, decision tables, UML analysis and architecture models, interface and data contracts, executable scenarios, runbooks. A gap in any layer reaches the layers below it through these artefacts. By the time it reaches the code it looks like a decision.

Where a rule is enforced says how it is lost: a system keeps applying it without its reason, a control stops when its operator leaves, and memory leaves with the person.

Preserving tacit and tribal knowledge in banking systems

2

Five layers of the lifecycle, each holding its own knowledge and each losing it in its own way. Specifications are not a sixth layer. They are the written form each layer takes: UML activity and sequence models for processes and requirements, UML component and class models and API contracts for architecture, Gherkin scenarios for requirements in executable form, decision tables for rules, runbooks for operations. The last sentence introduces the enforcement state, which the inventory later records for every rule: system, control or memory. The triggers are the familiar ones. Experts change department, retire or resign. They are tied up in other projects. The legacy systems they know best are the least documented.
