The framework: four stages at every layer, and a human turn in the middle

StageWhat happensWhat it produces
0. InventoryList what the experts alone know at each layer, from their tickets, their documents and the questions colleagues asked them. Rate each item by consequence, by uniqueness and by where it is enforced.The question list, in priority order
1. ObserveRead what exists at every layer: process models, requirements, decision tables, UML models, API and data contracts, code, runbooks. Run the code. Record what each artefact says, pinned to a version, and run the check for that layer.Grounded knowledge per layer, with each check’s findings
2. DraftAn on-premises AI drafts rules, explanations and diagrams from the observations. Every draft carries the label inferred.Inferred knowledge, with a confidence
3. ValidateThe expert confirms, rejects or explains each item. Each quirk is classified as deliberate, workaround, temporary or unknown.Asserted and intended knowledge
4. ExternaliseRules go to decision tables, terms to the glossary, reasons to decision records, procedures to runbooks. Each gets a check. The checks run in CI beside a test that does not depend on the code.Explicit, checked, living documentation

9

The four stages of the original core approach, with two changes. A stage zero is added: the inventory, so that the expert’s scarce hours go to what nobody else knows. Each stage is named by the kind of knowledge it produces, which is what makes the labels on every item possible. Stage 3 is the human turn. Nothing before it is authoritative, and nothing after it changes what was decided there.
