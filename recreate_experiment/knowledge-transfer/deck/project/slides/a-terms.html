Seven kinds of knowledge on three axes

TermAxisIn one lineExample
GroundedHow it is justifiedObserved in the system itself, pinned to a version.A stored value read from the code and reproduced by running it.
AssertedHow it is justifiedTaken on someone’s word.The cut-off is 16:00 because the operations lead says so.
DeductiveHow it is justifiedFollows with certainty from what is given.Amounts above the limit are rejected, read from an if statement.
InductiveHow it is justifiedGeneralised from many cases. The next case can break it.Every rejection carries a reason code, after ten thousand replays.
AbductiveHow it is justifiedA hypothesis that would explain a surprise. Not knowledge until confirmed.The batch skips 29 February because an old date library could not handle leap days.
TacitWhether it can be saidUsed without being fully stated.An operator who sees that a break looks wrong before any rule fires.
TribalWho holds itShared informally within a team, written nowhere.Never run end-of-day before the FX feed is confirmed.

Grounded knowledge is our own term. Tribal knowledge is an industry term with no academic source. Tacit has a strong sense, which cannot be fully told, and a weak sense, which is not yet written down. This approach mostly recovers the weak sense.

Sources: Peirce 1878 and 1903; Polanyi 1966; Nonaka 1994; Williamson 2000; Tsoukas 2003

A1

The five justification terms are stages of the pipeline. Observation gives grounded claims. Deduction from code is grounded and certain. Induction over traces and abduction about quirks give inferred claims. The expert’s confirmation turns an inferred claim into an asserted one, and into an intended one when the expert is the responsible authority. Tacit and tribal knowledge are the kinds not yet grounded anywhere, which is why the pipeline exists.
