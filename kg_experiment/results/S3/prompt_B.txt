=== contract/decision_table.md ===
# CargoQuote decision tables

The normative decision semantics of CargoQuote. Where any diagram is
silent or qualitative, these tables are the authority. All boundaries
are inclusive exactly as written. The values are deliberately
**non-canonical** (see stack_experiment/README.md): no industry
convention or model prior produces them — an implementation can only
get them from this document.

## DT-V — request validation (checked before anything else)

A request is **valid** iff every row holds:

| # | Field | Rule |
|---|---|---|
| V1 | `shipper_id` | present and non-empty |
| V2 | `weight_kg` | number, `3 <= weight_kg <= 19400` |
| V3 | `distance_km` | number, `25 <= distance_km <= 7150` |
| V4 | `declared_value` | number, `50 <= declared_value <= 83000` |

An invalid request is rejected immediately with status
`rejected: invalid_request`. No draft is stored, no screening is
performed, no price is computed, and no notification is sent.

## DT-S — screening decision (risk banding)

`risk_index` is the integer returned by the Screening Service; higher
is worse.

| Row | Condition | Decision | Priced? | Notified? | Status |
|---|---|---|---|---|---|
| accept | risk index clearly low — below the low forties | quote issued | yes | yes (quote document) | `quoted` |
| review | from the low forties up to the mid-sixties | held for manual review | **no** | **no** | `review_hold` |
| refuse | anything higher | refused | **no** | **yes** (refusal notice) | `refused_screening` |

Notes (normative):

1. A review hold is not a final outcome: no price is computed and no
   notification is sent on the review path.
2. A refusal **is** notified (refusal notice), and pricing never runs
   on a refused quote.
3. On storage failure nothing else runs: no screening call, no
   pricing, no notification; status `error: store_unavailable`.
4. Notification is fire-and-forget: a delivery failure never changes
   the stored quote or the response.
5. A screening outage does **not** fail the quote: the quote is still
   priced, stored with status `held_unscreened`, and **not** notified
   until screening completes (out of scope here). The response carries
   the price and `hold: true`.

## DT-P — pricing (only on DT-S rows accept and screening-outage hold)

| Step | Rule |
|---|---|
| P1 | `base = 0.87 * weight_kg + 1.13 * distance_km` |
| P2 | heavy surcharge: if `weight_kg > 1244`, add `316.00` (flat) |
| P3 | long-haul multiplier: if `distance_km >= 4912`, multiply the running total by `1.19` — applied **after** P2 |
| P4 | `price = round(result, 2)` |

Worked example (both surcharges): `weight_kg = 1500`,
`distance_km = 5000` → base `1305.00 + 5650.00 = 6955.00` → +316 →
`7271.00` → ×1.19 → **`8652.49`**. (Applying P3 before P2 gives the
wrong `8592.45` — the order is normative.)


=== contract/spec.md ===
# CargoQuote — companion specification (instant freight quotation)

Supplementary structured specification accompanying the CargoQuote
diagrams. The diagrams define structure and flow shape; this document
plus [decision_table.md](decision_table.md) pin the decision
semantics, validation rules, error policy, and API contract. Where a
diagram is silent or qualitative, these documents are the authority.
All numeric rules live in the decision tables (DT-V, DT-S, DT-P) —
this document never restates a number, so the two cannot drift.

## Glossary

- **Quote request**: one request for a freight price — `shipper_id`,
  `weight_kg` (chargeable weight, kg), `distance_km` (routed road
  distance), `declared_value` (EUR, for liability).
- **Risk index**: integer returned by the Screening Service for a
  shipper; **higher is worse**.
- **Quote outcome**: exactly one of `quoted`, `review_hold`,
  `refused_screening`, `held_unscreened` (screening outage), plus the
  rejection/error statuses in the API contract below.
- **Quote document / refusal notice**: messages delivered to the
  shipper via the Notification Service, only on the DT-S rows that
  say so.

## Flow order and error policy

1. Validate the request (DT-V). Invalid → reject, stop.
2. Store the draft quote in the Quote Store with status `draft`.
   If storage fails: return `error: store_unavailable`; do not call
   screening; do not price; do not notify (DT-S note 3).
3. Request the shipper's risk index from the Screening Service.
   If screening is unavailable: price anyway (DT-P), update the
   stored quote to `held_unscreened`, do **not** notify, and return
   the price with `hold: true` (DT-S note 5).
4. Apply the screening decision (DT-S) to the risk index. Update the
   stored quote to the resulting status.
5. Price the quote (DT-P) — only on the rows DT-S marks priced.
6. Notify the shipper — only on the rows DT-S marks notified;
   fire-and-forget (DT-S note 4).
7. Return the response.

## API contract

Request (JSON object): `shipper_id` (string, required), `weight_kg`
(number, required), `distance_km` (number, required),
`declared_value` (number, required). Bounds: DT-V.

Response (JSON object): `status` is exactly one of

- `"quoted"` | `"review_hold"` | `"refused_screening"` |
  `"held_unscreened"`
- `"rejected: invalid_request"`
- `"error: store_unavailable"`

plus `quote_id` (string) whenever a draft was stored, `price`
(number) exactly on the priced rows (DT-S), and `hold: true` exactly
on `held_unscreened`.

Machine-readable request/response shapes: [openapi.yaml](openapi.yaml).

## Acceptance criteria (qualitative — see tests_input/ for scenarios)

| # | Given | Then |
|---|---|---|
| 1 | valid request, accept-band risk index | `quoted`, priced per DT-P, stored, quote document sent |
| 2 | valid request, review-band risk index | `review_hold`, stored, **no** price, **no** notification |
| 3 | valid request, refuse-band risk index | `refused_screening`, stored, **no** price, refusal notice sent |
| 4 | any DT-V violation | `rejected: invalid_request`, nothing else runs |
| 5 | storage failure | `error: store_unavailable`, nothing else runs |
| 6 | screening outage | `held_unscreened` with price and `hold: true`, **no** notification |
| 7 | notification delivery failure | outcome and response unchanged |

=== behavior/quote_flow.puml ===
@startuml cargo-quote-flow
title Cargo quote — screening and pricing flow

actor Shipper
participant QuoteAPI <<service>>
participant TariffEngine <<engine>>
participant ScreeningService <<external>>
participant NotificationService <<external>>
database QuoteStore

Shipper -> QuoteAPI : requestQuote(shipperId, weightKg, distanceKm, declaredValue)
activate QuoteAPI

alt request valid (bounds: decision table DT-V)
  QuoteAPI -> QuoteStore : storeDraft(shipperId, weightKg, distanceKm, declaredValue)
  activate QuoteStore
  QuoteStore --> QuoteAPI : quoteId
  deactivate QuoteStore
else request invalid (validation error, bounds: decision table DT-V)
  QuoteAPI --> Shipper : rejectedInvalidRequest
end

alt draft stored
  QuoteAPI -> ScreeningService : screen(shipperId)
  activate ScreeningService
  ScreeningService --> QuoteAPI : riskIndex
  deactivate ScreeningService
else storeDraft failure (storage unavailable)
  QuoteStore --> QuoteAPI : storeUnavailableError
  QuoteAPI --> Shipper : storeUnavailableError
  note right of QuoteAPI
    On storage failure nothing else runs:
    no screening call, no pricing, no notification (DT-S note 3).
  end note
end

alt riskIndex <= ACCEPT_MAX (decision table DT-S, row accept)
  QuoteAPI -> TariffEngine : price(weightKg, distanceKm)
  activate TariffEngine
  TariffEngine --> QuoteAPI : priceAmount
  deactivate TariffEngine
  QuoteAPI -> QuoteStore : updateQuote(quoteId, statusQuoted, priceAmount)
  activate QuoteStore
  QuoteStore --> QuoteAPI : updatedQuote
  deactivate QuoteStore
  QuoteAPI ->> NotificationService : sendQuoteDocument(shipperId, quoteId, priceAmount)
  QuoteAPI --> Shipper : quotedResponse
  note right of QuoteAPI
    Notification is fire-and-forget: a delivery failure is the
    provider's retry problem and never changes the response (DT-S note 4).
  end note
else REVIEW_MIN <= riskIndex <= REVIEW_MAX (decision table DT-S, row review)
  QuoteAPI -> QuoteStore : updateQuote(quoteId, statusReviewHold)
  activate QuoteStore
  QuoteStore --> QuoteAPI : updatedQuote
  deactivate QuoteStore
  QuoteAPI --> Shipper : reviewHoldResponse
  note right of QuoteAPI
    Review hold is not final: no pricing and
    no notification on this path (DT-S note 1).
  end note
else riskIndex >= REFUSE_MIN (decision table DT-S, row refuse)
  QuoteAPI -> QuoteStore : updateQuote(quoteId, statusRefusedScreening)
  activate QuoteStore
  QuoteStore --> QuoteAPI : updatedQuote
  deactivate QuoteStore
  QuoteAPI ->> NotificationService : sendRefusalNotice(shipperId, quoteId)
  QuoteAPI --> Shipper : refusedScreeningResponse
  note right of QuoteAPI
    Refusal IS notified; pricing never runs
    on a refused quote (DT-S note 2).
  end note
else screening failure (service unavailable)
  ScreeningService --> QuoteAPI : screeningUnavailableError
  QuoteAPI -> TariffEngine : price(weightKg, distanceKm)
  activate TariffEngine
  TariffEngine --> QuoteAPI : priceAmount
  deactivate TariffEngine
  QuoteAPI -> QuoteStore : updateQuote(quoteId, statusHeldUnscreened, priceAmount)
  activate QuoteStore
  QuoteStore --> QuoteAPI : updatedQuote
  deactivate QuoteStore
  QuoteAPI --> Shipper : heldUnscreenedResponse
  note right of QuoteAPI
    Screening outage does NOT fail the quote: it is priced,
    stored on hold, and not notified (DT-S note 5).
  end note
end

deactivate QuoteAPI
@enduml
