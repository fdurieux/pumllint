pumllint · a session for functional analysts

Checked before it is handed on

A 45-minute session for functional analysts and process engineers. It places pumllint in Legible, a programme that puts quality checks on everything written before code, maps what goes wrong and which tools exist across the delivery pipeline, and ends with a live demo: one credit application, drawn right and drawn wrong, checked in a few seconds.

A few words first

Legible
A programme that makes the information upstream of code (requirements, processes, models, decisions) readable by people and machines, and checks it before anyone builds on it.
PlantUML
A way of drawing diagrams by writing short text files. The text is turned into a picture, and the files can be stored and reviewed like code.
pumllint
A linter for PlantUML: it reads a diagram and points out what the next reader would have to guess, such as a decision that does not say which way is "yes". Each finding has a severity, and each diagram gets a maturity level from 1 to 5.

What the session covers

  1. Legible. Why the information code is built from deserves the same checks code has had for twenty years.
  2. The problem. What goes wrong before code, stage by stage across the delivery pipeline, and two examples of diagrams that render but do not make sense.
  3. The contribution. Which tools check which artefacts today, where pumllint sits, and the one result that was measured.
  4. In practice. A credit application as four linked diagrams, compliant and not, why each passes or fails, and the same set live on a laptop.
  5. The decision. Run a proof of concept or not.
